    Computer System Architecture

    A computer is a modern electronic machine designed for high-speed computation. It can perform both numerical and logical computation and can also store information. It is a modern intelligent electronic device that runs according to a program and processes massive amounts of data automatically and at high speed.

    Classification of computers (by performance and flexibility):

    • Special-purpose computers (embedded systems)
    • General-purpose computers (ordinary PCs), which can be further divided as follows:

    A computer system consists of two major parts: the hardware system and the software system.

    • Hardware: The physical part of the computer, consisting of tangible electronic components and optical, electrical, and mechanical devices.
    • Software: Programs with various specific functions written in advance by people. Software is intangible and is usually stored on media such as optical discs and magnetic disks.

    Computer hardware and software are logically equivalent.

    A computer system can be viewed in terms of its computer architecture (external architecture) and its computer organization (internal architecture).

    • Computer architecture (external architecture): The attributes of a computer system as seen by the programmer, that is, its conceptual structure and functional behavior. Examples include the instruction set, addressing modes, and data types.
    • Computer organization (internal architecture): How the attributes specified by the architecture are implemented. Examples include which components the machine is built from and how they are interconnected (adders, control logic, etc.).

    The five major components of computer hardware:

    • Arithmetic unit: Performs arithmetic and logical operations and temporarily stores intermediate results.
    • Memory: Stores data and programs.
    • Controller: Controls and directs the input and execution of programs and data and the handling of results.
    • Input devices: Convert information from forms familiar to people into forms the machine can recognize.
    • Output devices: Convert the machine's results into forms familiar to people and present them.

    In a computer, a continuous sequence of information is called a stream. Streams are generally divided into:

    • Instruction stream (IS): The sequence of tasks (code) executed by the machine.
    • Data stream (DS): The data (operands) processed by the instructions.

    Computer architectures can therefore be classified by their level of parallelism. This scheme is called Flynn's taxonomy.

    The von Neumann architecture:

    • Five major components; early machines were centered on the arithmetic unit.
    • Data and instructions are represented in binary, stored with equal status in memory, and accessed by address.
    • An instruction consists of an opcode and an address field, and instructions are stored sequentially in memory.
    • Core idea: Instructions and data are treated alike and stored in the same memory, and the CPU executes instructions automatically by address.

    Arithmetic Unit

    The arithmetic unit is commonly called the Arithmetic Logic Unit (ALU). The number of bits it can process at once is called the machine word length.

    Operands are generally binary numbers, where 0 represents a low voltage or no pulse and 1 represents a high voltage or a pulse. Their length is generally a power of 2.

    The arithmetic unit usually contains at least three core registers: the accumulator (ACC), the multiplier-quotient register (MQ), and the operand register (X).

    Controller

    The basic task of the controller is to repeat the following three phases over and over:

    1. Fetch: Retrieve an instruction from memory according to the instruction sequence arranged by the program.
    2. Decode: Analyze the instruction, determine the operation to perform (the opcode), and locate the operand addresses according to the addressing information.
    3. Execute: Perform the operation according to the operand addresses and the opcode.

    Components of the controller:

    • Program Counter (PC): Holds the address of the next instruction to be executed. It increments automatically and can thus form the address of the next instruction by itself.
    • Instruction Register (IR): Holds the instruction currently being executed by the CPU.
    • Control Unit (CU): Analyzes the operation required by the current instruction and issues the corresponding sequence of micro-operation commands.

    We generally use LDR r0,address to denote loading the contents of the memory location at address into register r0. Taking the fetch of this instruction as an example, the RTL notation for the fetch (FETCH) phase is:

    RTL
    FETCH [MAR] <- [PC]     ;copy the PC into the memory address register
      [PC] <- [PC]+4    ;increment the PC to point to the next instruction
      [MBR] <- MAR  ;read the instruction at the address in MAR
      [IR] <- [MBR]     ;copy the instruction from the MBR to the IR
    iTip

    Registers are accessed by name rather than by address.

    iTip

    The Memory Address Register (MAR) holds the address of the memory location being accessed by a read or write operation.

    iTip

    The Memory Buffer Register (MBR) holds data just read from memory or data about to be written to memory. In modern computer architecture, the Memory Data Register (MDR) and the MBR refer to the same thing.

    iTip

    In modern CPU designs, the MAR and MDR (or MBR) are usually integrated inside the CPU to increase integration density, but logically they belong to the interface of main memory.

    Memory

    Taking main memory as an example, it consists of the storage array, various logic components, and control circuitry.

    Storage array ← memory word ← memory location ← storage element

    • Storage element (storage cell): Each can store one binary digit (bit).
    • Memory location: Can store a string of binary digits called a memory word; the number of bits is the memory word length. It is the smallest unit the CPU accesses by address.
    • Storage array: The whole formed by a large number of densely arranged memory locations.
    • Memory address: Each memory location is numbered, and its number is called the address of that location.

    Writing and reading all bits of a memory word by the address of its memory location is called access by address (memory access).

    Performance Metrics

    MOPS (Million Operations Per Second): Millions of operations per second (usually INT4 or INT8, with low precision requirements).

    MFLOPS (Million Floating-point Operations Per Second): Millions of floating-point operations per second (high precision requirements; mainly used to measure floating-point capability in high-performance and scientific computing).

    CPU performance:

    Almost all digital electronic circuits generate a continuous stream of electrical pulses at fixed intervals, called the clock. The clock cycle (tick) is the smallest unit of time in which a computer performs an operation, and its reciprocal is the clock rate $f$. Several clock cycles form a CPU cycle (machine cycle), which is usually defined as the shortest time needed to read one instruction word from memory.

    The relationship among program execution time (TCPU), clock rate ($f$), and the total number of clock cycles (CLK, Clock): $$TCPU=CLK/f=CLK∗TCLK$$ CPI (Cycles Per Instruction): The average number of clock cycles needed to execute one instruction. It reflects the computer's organization and the structure of its instruction set.

    MIPS (Million Instructions Per Second): The number of instructions executed per unit time, in millions per second.

    IC (Instruction Count): The number of instructions executed while running a program. It reflects the structure of the instruction set and compiler technology.

    $$CPI=CLK/IC$$

    Therefore

    $$\boxed{TCPU=CPI∗IC/f}$$

    Therefore, to shorten program execution time, we need to optimize the three parameters $CPI,IC,f$.

    Suppose the computer has $n$ instruction classes, where instructions of class $i$ take $CPI_i$ clock cycles each and occur $IC_i$ times in the program. Then

    $$TCPU=CLK/f=\sum_i(IC_i∗CPI_i)/f$$

    The overall $CPI=\sum_i(IC_i/IC)\times CPI_i$, that is, the average of the per-class CPIs weighted by their frequencies.

    Moreover, different factors affect different parameters: the algorithm, programming language, and compiler mainly affect $CPI$ and the instruction count IC, whereas the instruction set architecture (ISA) affects CPI, IC, and the clock rate $f$.

    Integrated Circuit Manufacturing

    Integrated circuit cost = (die cost + die testing cost + packaging cost) / final test yield

    Die cost = wafer cost / (dies per wafer × die yield)

    Dies per wafer = wafer area / die area − $\frac{\pi×\text{wafer diameter}}{\sqrt{2×\text{die area}}}$

    Die yield = $\text{wafer yield}×(1+\text{defect density}×\text{die area}/\alpha)^{−\alpha}$

    Here $\alpha$ is a constant, typically $3−4$.

    Computational Efficiency

    Execution time is the only valid and unimpeachable measure of performance.

    A natural question in the history of computing is whether computational efficiency can be improved without limit. Two laws address this question:

    • Amdahl's law

    For a piece of code, let the fraction that can be accelerated by parallel computation be $p$ and the fraction that must run serially be $1−p$. If the accelerable part is made $n$ times faster, then

    the overall speedup, defined as the ratio of execution time before and after the optimization, is $$\boxed{S=\frac{1}{(1−p)+\frac{p}{n}}}$$

    It follows easily that $$\lim \limits_{n→+∞}S=\frac{1}{1−p}$$

    Therefore, for a fixed task, continually upgrading the hardware yields diminishing returns: the improvement in efficiency is bounded.

    • Gustafson's law

    As the number of processors increases, the size of the parallel part grows accordingly, while the serial part stays relatively fixed.

    Let the number of processors be $n$, and during large-scale parallel execution let the serial fraction be $s$ and the parallel fraction be $1−s$.

    Then the scaled speedup is $$\boxed{S=n+(1−n)\times s=s+n \times (1−s)}$$

    Hence, within a fixed amount of time, the scaled speedup can keep increasing as processors are added.

    Power Wall

    The dynamic power of CMOS circuits comes mainly from switching and is approximately

    $$P \propto \text{capacitive load} \times \text{voltage}^2 \times \text{switching frequency}$$

    Raising the clock rate increases power, so power can be reduced by lowering the capacitive load, the voltage, or the frequency. However, the voltage cannot be lowered much further (too low a voltage causes leakage current to rise sharply), and there is no effective way to remove more heat. Together these two factors form the power wall: it ended the path of improving performance simply by raising the clock rate and forced the industry to move from uniprocessors to multicore (multiprocessor) designs that continue to improve performance through parallelism.

    Program Compilation

    Computer languages are divided into high-level languages and low-level languages (machine language and assembly language).

    A language is generally implemented in one of two ways:

    • Compilation: The source program is translated into a machine-language object program, which is then executed.
    • Interpretation: An interpreter for the source language is implemented on the target machine, and it directly interprets and executes the source program.
    iTip

    Language implementations are diverse; pure compilation and pure interpretation are merely two extremes:

    • Common implementations of C and Fortran can be regarded as fairly pure compilation.
    • Early BASIC, DOS batch (.bat) files, and some current scripting-language implementations use essentially pure interpretation.
    • Java and similar languages sit in between (using intermediate forms such as bytecode or syntax trees).

    Translating and Starting a Program

    Going from source code to a running program requires four cooperating tools:

    • Compiler: Translates a high-level language such as C into assembly language.
    • Assembler: Translates an assembly program into a machine-language object module. It handles pseudoinstructions and uses a symbol table, consisting of symbol–address pairs, to keep track of labels used in branches and data transfer instructions.
    • Linker: Places the independently assembled code and data modules in memory according to their symbols, determines the addresses of labels, patches internal and external references, resolves all undefined labels, and finally produces an executable file.
    • Loader: Loads the executable file into memory and starts it running.

    Dynamically linked libraries (DLLs): Libraries are linked and loaded only at run time. Compared with static linking, DLLs are easier to update and save space; static linking starts faster and is easier to understand but makes upgrades harder.

    Instruction Set Architecture

    Instruction: A command that directs the computer to perform a certain operation.

    Instructions can be classified as:

    • Microinstructions
    • Macroinstructions
    • Machine instructions

    Instruction Set (IS): The set of all machine instructions a computer can execute.

    Instruction Set Architecture (ISA): A complete architectural specification. It specifies not only which instructions exist but also how these instructions interact with the hardware; it is the external architecture of the computer.

    The format and functions of the instructions directly affect the machine's hardware structure, its system software, and its range of applications.

    Computer family: A series of computers with the same basic instruction set and the same basic architecture.

    Requirements of a well-designed instruction set:

    • Completeness
    • Efficiency
    • Regularity
    • Compatibility

    Key principles:

    • Instructions are represented as numbers.
    • Programs are stored in memory and read and written just like data.

    Instruction Formats

    An instruction consists of an opcode (OP) and operand addresses (A), and instructions are stored sequentially in memory as binary codes.

    Opcode: Specifies the operation the instruction performs. Address field: Specifies where the operands involved in the operation are stored.

    • Three-address instructions: (A1)OP(A2) → (A3)
    • Two-address instructions: (A1)OP(A2) → (A1/A2)
    • One-address instructions: (A1)OP(ACC) → (ACC)
    • Zero-address instructions: e.g., no-operation (NOP), halt (HLT), return from function (RET), return from interrupt (IRET)

    Instruction word length: The number of bits in an instruction word, usually a multiple of 8.

    • Single-word instructions: The instruction length equals the machine word length (common in early machines).
    • Half-word instructions: The instruction length is half the machine word length.
    • Double-word/multi-word instructions: The instruction length is two or more times the machine word length.
    • They provide enough address bits to address any location in memory.
    • Fetching a complete instruction requires multiple memory accesses, which slows the CPU and uses more storage.
    EExample

    Suppose the instruction length is 16 bits, each operand address field is 6 bits, and there are three instruction formats: zero-address, one-address, and two-address.

    1. With a fixed-length opcode, a two-address instruction has $16-6-6=4$ opcode bits, so there are $2^4=16$ opcodes in total.
    2. With the expanding opcode technique, if there are X two-address instructions and Y one-address instructions, the maximum number Z of zero-address instructions satisfies $$2^{12}X+2^{6}Y+Z\le2^{16}$$

    Addressing Modes

    Instruction addressing: Locating the next instruction. It is generally divided into sequential addressing (the PC increments automatically) and jump addressing (branch and jump instructions modify the PC).

    Data addressing: Determining the actual address of an operand.

    • Immediate addressing: MOV R0, #15
    • Register addressing: ADD R1, R2 (the operand is in a register)
    • Register indirect addressing: LOAD R1, (R2) (R2 holds the memory address of the operand)
    • Direct addressing: LOAD R1, [1000H]
    • Indirect addressing: LOAD R1, @[1000H]

    Byte Ordering

    With byte addressing, a word is 32 bits and a byte is 8 bits, so four bytes hold one word; consecutive word addresses therefore differ by 4.

    • Big-endian: The address of the leftmost (most significant) byte is used as the word address.
    • Little-endian: The address of the rightmost (least significant) byte is used as the word address.
    • RISC-V is little-endian.

    EExample

    Consider the following code:

    RISC-V
    ld x6, 0(x7)
sd x6, 8(x7)

    Suppose register x7 contains the address 0x10000000 and the data at that address is 0x8877665544332211. After sd executes, what (double)word is stored starting at 0x10000008?

    1. On a big-endian machine, the doubleword 0x8877665544332211 is stored starting at 0x10000008.
    2. On a little-endian machine, the doubleword 0x8877665544332211 is stored starting at 0x10000008.

    (ld reads the whole doubleword into x6 and sd writes it back unchanged, so the doubleword's value does not depend on byte order and is the same on both machines; only the order of the individual bytes in memory differs.)

    If ld is replaced by lw and sd by sw, i.e.,

    RISC-V
    lw x6, 0(x7)
sw x6, 8(x7)
    1. On a big-endian machine, the word 0x88776655 is stored starting at 0x10000008.
    2. On a little-endian machine, the word 0x44332211 is stored starting at 0x10000008.

    The key difference between the two:

    • lw (Load Word): reads 32 bits (4 bytes) of data from memory.
    • ld (Load Doubleword): reads 64 bits (8 bytes) of data from memory.

    CISC and RISC

    Complex Instruction Set Computer (CISC)

    Representative: the x86 architecture of Intel and AMD.

    • Instructions usually have two operands, one of which is a memory operand.
    • Advantages: Arithmetic instructions can use memory locations directly as operands, so instructions are compact and space-efficient.
    • Disadvantages: Instructions take many cycles to execute, memory operands occupy many bits in the instruction, and dependences between instructions are harder to determine.

    Reduced Instruction Set Computer (RISC)

    Representatives: the ARM architecture and RISC-V.

    • Instructions usually have three operands, all of which are registers.
    • Each instruction completes in one machine cycle.
    • Only load and store instructions access memory; all other operations are performed between registers.
    • Implementations commonly use separate instruction and data caches (a Harvard-style cache organization) so that instructions and data can be fetched simultaneously.
    • Advantages: Fixed-length instructions, simple hardware, few clock cycles per instruction, and easy to implement at high clock rates.
    • Disadvantages: More instructions are needed to complete the same task, and fixed-length instructions waste space.

    Simple Instruction Sets

    1. Stack instruction sets

    Instructions in a stack instruction set are generally zero-address instructions.

    • Advantages: Very compact code (short instructions); simple compiler implementation.
    • Disadvantages: The top of the stack easily becomes a performance bottleneck; data cannot be accessed randomly, so flexibility is poor.
    • Typical examples: early Burroughs computers and the Java Virtual Machine (JVM).
    1. Accumulator instruction sets

    An accumulator instruction set generally has only one special register, the accumulator (ACC). Instructions are usually one-address instructions: one operand is implicitly in the accumulator, and the instruction specifies only the other operand (usually in memory). For example, ADD X means ACC = ACC + Memory[X].

    • Advantages: Extremely simple hardware; saves register resources.
    • Disadvantages: Because there is only one accumulator, programs must frequently move data to and from memory (memory traffic), which lowers efficiency.
    • Typical examples: EDSAC, the early 8051 microcontroller, and the MOS 6502.

    The RISC-V Instruction Set

    RISC-V is one of the best-known and most successful open, free, and modern instruction set architectures today (earlier open ISAs such as OpenRISC already existed, so it is not the "first"). It consists of a base integer instruction set (RV32I/RV64I) and several optional extensions.

    For the details of the RISC-V instruction set, see the official specification.

    Examples of RISC-V instructions:

    add rd,rs1,rs2: R-type instruction, opcode op=0110011, destination register rd, source registers rs1 and rs2.

    addi rd,rs1,i: I-type instruction, opcode op=0010011, destination register rd, source register rs1, immediate i.

    ld rd,offset(rs1): I-type instruction, opcode op=0000011, destination register rd, base register rs1, offset offset. It reads 8 bytes from the address given by the contents of rs1 plus offset and places them in rd (memory → register).

    sd rs2,offset(rs1): S-type instruction, opcode op=0100011, source data register rs2, base register rs1, offset offset. It stores the 8 bytes in rs2 to memory at address rs1 + offset (register → memory).

    Conditional branch instruction: beq x1,x2,offset

    To make the decoding hardware as simple as possible, RISC-V makes a clever physical design choice: the positions of the source registers (rs1, rs2) and the destination register (rd) are exactly the same in all formats. As a result, the CPU can start reading the register file the instant it has the instruction, without first knowing which instruction it is.

    Compared with MIPS, RISC-V incorporates lessons learned over the past 30 years:

    1. No delay slots: For pipeline efficiency, MIPS requires the instruction after a jump or branch (the delay slot) to be executed. This makes life hard for compilers. RISC-V solves the problem with modern branch predictors and no longer needs delay slots.
    2. No condition codes: RISC-V conditional branches (e.g., beq) compare two registers directly, which simplifies the design of the state machine.
    3. Sign extension of immediates: The layout of RISC-V immediate bits looks messy (the fields are split up), but the design keeps the sign bit in the same position so that the circuit paths for sign extension are identical in length, which helps raise the clock rate.

    RISC-V Instruction Format Fields

    Field layout of each format (32 bits in total):

    • R-type (add, sub): funct7(7) | rs2(5) | rs1(5) | funct3(3) | rd(5) | opcode(7)
    • I-type (lw, addi): imm[11:0](12) | rs1(5) | funct3(3) | rd(5) | opcode(7); the immediate is a 12-bit two's-complement number.
    • S-type (sw; the immediate is split into two parts so that the positions of rs1/rs2 match the R-type): imm[11:5] | rs2 | rs1 | funct3 | imm[4:0] | opcode

    Design principles: simplicity favors regularity, smaller is faster, and good design demands good compromises. The two key principles of building computers are "instructions are represented as numbers" and "programs are stored in memory to be read or written, just like data" (the stored-program concept).

    Logical and Shift Operations

    • Shifts: Logical shifts fill with 0; arithmetic right shifts fill with the most significant (sign) bit. Shifts by an immediate: slli/srli/srai; shifts by a register amount: sll/srl/sra.
    • AND: Often used for masking, i.e., clearing certain bits to 0 (the other source operand serves as the mask).
    • OR: Used to set certain bits to 1.
    • XOR: Yields 0 for equal bits and 1 for different bits; XOR with all ones (111…1) implements bitwise NOT.

    Decision-Making and Branch Instructions

    Conditional branches: beq (equal), bne (not equal), blt/bge (signed less than / greater than or equal), and bltu/bgeu (unsigned). Set instructions: slt/slti/sltu/sltiu set x[rd]=1 when the first operand is less than the second (slt/sltu compare x[rs1] with x[rs2]; slti/sltiu compare x[rs1] with an immediate). They are often combined with branches to implement complex conditions.

    Comparators are not necessarily used to perform subtraction; conversely, subtraction is often used to implement comparison.

    Hardware Support for Procedures

    • jal rd, label (jump and link): Jumps to the target and stores the return address PC+4 in rd (usually x1/ra). The encoded immediate field is 20 bits (the actual offset is 21 bits, with the lowest bit implicitly 0). It is used for procedure calls.
    • jalr rd, offset(rs1) (jump and link register): Jumps to rs1+offset with a 12-bit immediate. jalr x0, 0(x1) is commonly used to return from a function.

    During a procedure call, the stack is used to save the return address and the registers that must be preserved: before the call, addi sp, sp, -k allocates stack space and sw saves the registers; before returning, lw restores them and addi sp, sp, k pops the stack. Recursive and nested calls rely especially on the stack to save each level's context (e.g., implementations of recursive functions such as fact and sum). Characters are stored with lb/sb (C uses 8 bits and Java uses 16 bits to represent a character); lb sign-extends and lbu zero-extends.

    Large Immediates and Addressing Modes

    lui rd, imm (load upper immediate): Loads a 20-bit constant into bits 31–12 of the register and fills the lower 12 bits with 0; combined with addi, it can build a 32-bit constant.

    Addressing modes:

    • Immediate addressing: The operand is a constant within the instruction.
    • Register addressing: The operand is in a register.
    • Base (displacement) addressing: Address = register value + constant in the instruction (e.g., lw/sw).
    • PC-relative addressing: Address = PC + constant in the instruction. The branch immediate is 13 bits (with the lowest bit 0), giving a range of about PC−4096 to PC+4094 (±4 KiB); jal has an actual offset of 21 bits (a 20-bit encoded field), giving a range of about ±1 MiB.

    CPU Design

    CPU implementation approaches:

    • Single-cycle: instruction cycle = machine cycle = clock cycle
    • Multicycle: instruction cycle = $m$ machine cycles = $m$ clock cycles

    Regardless of the instruction, execution usually goes through these five logical steps:

    1. Instruction fetch (IF): Read the instruction from the Instruction Memory at the address in the PC (program counter).
    2. Instruction decode (ID): The Control unit generates control signals from the instruction's opcode (bits 6–0 in RISC-V), while data are read from the register file (Registers).
    3. Execute (EX): The ALU (arithmetic logic unit) performs addition, subtraction, logical operations, or address calculation.
    4. Memory access (MEM): Only load and store instructions use the Data Memory.
    5. Write-back (WB): Write the result back to the register file.

    Single-Cycle Processor Design

    • R/I-type instructions: Fetch the instruction and read the registers; a Mux selects whether the ALU operates on a register and an immediate or on two registers; the ALU computes the result, and a Mux determines whether the result is written back to the register file.
    • ld instruction: Fetch the instruction and read the registers; a Mux selects whether the ALU operates on a register and an immediate or on two registers; the ALU computes the target memory address. The value at that address is read from memory, and finally a Mux determines whether the result is written back to the register file.
    • sd instruction: Fetch the instruction and read the registers; a Mux selects whether the ALU operates on a register and an immediate or on two registers; the ALU computes the target memory address, and finally the data are stored at that address in memory.
    • beq instruction: Fetch the instruction and read the registers; a Mux selects whether the ALU operates on a register and an immediate or on two registers. The ALU computes the difference of the two operands while a separate adder computes the branch target address; the ALU's Zero output is ANDed with the Branch control signal to drive the Mux that selects the next address, which is finally written into the PC.

    In a single-cycle processor, the clock cycle is determined by the critical path, i.e., the instruction with the longest execution time, which is usually the load instruction. However, this wastes part of the clock cycle for instructions that execute faster and prevents raising the clock rate. To overcome this, we implement a multicycle processor design.

    For a single-cycle processor, it is easy to see that $CPI=1$ for every instruction.

    Multicycle Processor Design

    Because the different steps of each instruction are completed in separate clock cycles, a multicycle processor needs only one ALU.

    A multicycle processor needs a write control signal for the PC. In a single-cycle processor, one instruction is executed per cycle, so the PC can simply be incremented by 4 every cycle. In a multicycle processor, however, an instruction is not fetched every cycle, so the PC must be controlled to increment by 4 only when an instruction is fetched.

    Every instruction requires instruction fetch and decode (register read), which take two cycles.

    • R/I-type instructions: The result is computed in the third clock cycle and written back in the fourth, $CPI=4$.
    • ld instruction: The address is computed in the third clock cycle, memory is read in the fourth, and the value in the MDR is written back in the fifth, $CPI=5$.
    • sd/sw instructions: The address is computed in the third clock cycle and memory is written in the fourth, $CPI=4$.
    • beq/jump instructions: The two registers are compared and the PC is updated in the third clock cycle, $CPI=3$.

    Pipelining

    Pipelining: Modern CPUs divide instruction execution into many small stages. It is like an automobile assembly line: although building one car takes a long time, all stations work simultaneously, so a car comes off the line every clock cycle.

    Consider a pipeline processing $n$ tasks. Its performance can be analyzed as follows:

    • Throughput $TP=\frac{n}{T_{\text{pipelined}}}$ (the number of tasks completed per unit time)
    • The maximum throughput is determined by the time required by the slowest stage, which becomes the bottleneck of the pipeline.
    • Ways to remove the bottleneck: subdivide the bottleneck stage, or replicate the bottleneck stage.
    • Speedup $S=\frac{T_{\text{non-pipelined}}}{T_{\text{pipelined}}}$
    • If the pipeline has $m$ stages, each taking $\Delta t_0$, then $\boxed{S=\frac{nm\Delta t_0}{m\Delta t_0+(n−1)\Delta t_0}=\frac{nm}{m+n−1}}$
    • Efficiency E: The utilization of the pipeline hardware.

    For the RISC-V instruction set, each instruction needs at most five steps, so we design a five-stage pipeline and add four pipeline registers.

    In some cases, pipelining causes the current instruction to need the result of a previous instruction that has not yet finished; these are called dependences. They can lead to hazards.

    • Structural dependence: Multiple instructions need the same resource. When overlapping instructions require more hardware resources than are available, the resulting resource conflict produces a Structural Hazard.
    • Data dependence: An instruction needs the result of an earlier instruction. When these instructions overlap in the pipeline, a Data Hazard may occur.
    • Control dependence: A dependence caused by branch instructions (such as jumps and conditional tests): the execution of subsequent instructions depends on the outcome of the branch. A Control Hazard occurs when the pipeline encounters a branch or another instruction that changes the PC.

    Structural Hazards

    If the CPU has only one memory that stores both instructions and data, the pipeline will suffer a structural hazard.

    There are two ways to resolve this hazard:

    • Insert a bubble
    • Harvard architecture: Unlike the von Neumann architecture, the Harvard architecture physically separates instruction storage and data storage, each with its own bus, so instructions and data can be read simultaneously. This also alleviates the von Neumann bottleneck. However, a pure Harvard architecture needs two buses and two memory systems, which increases board routing and hardware design costs.

    Control Hazards

    In the basic pipeline, the outcome of a branch is not known until a late stage (around the MEM stage), so several instructions following the branch may be fetched into the pipeline incorrectly, causing stalls.

    Clearly, we can insert bubbles to resolve this hazard, but that wastes a lot of time. Another approach is branch prediction.

    Branch prediction aims for two goals: predictions should be as accurate as possible (a high prediction hit rate), and the recovery cost of a misprediction should be as small as possible (flushing wrong-path instructions as early as possible).

    Dynamic branch prediction: Hardware records the past behavior of branches to predict their future direction. The basic component is the branch history table (BHT/PHT), whose entries are commonly 2-bit saturating counters (the prediction direction changes only after two consecutive mispredictions, avoiding oscillation at loop boundaries). Depending on how history information is used, predictors can be classified as:

    • Local prediction: Uses only the branch's own history. Each branch (indexed by the low-order bits of its PC) has a local branch history register (BHR) that records its most recent outcomes; this history pattern then indexes the saturating counters in the pattern history table (PHT). It is good at capturing the regular behavior of an individual branch (e.g., a loop pattern such as "taken 3 times, not taken once").
    • Global prediction: Uses a single global history register (GHR) shared by all branches, which records the combined outcomes of the most recently executed branches; this history (often XORed with the PC, as in gshare) indexes the PHT. It is good at capturing correlations between branches (the outcomes of earlier branches determine the direction of later ones).
    • Tournament predictor: Maintains both a local and a global predictor, plus a selector (chooser/meta-predictor, also a table of 2-bit saturating counters) that records which predictor has historically been more accurate for each branch and dynamically selects its output. The selector moves one step toward whichever predictor was correct, so it automatically picks the more suitable prediction scheme for each branch. A typical implementation is the Alpha 21264.

    Instruction-Level Parallelism (ILP)

    Instruction-Level Parallelism (ILP): Executing multiple mutually independent instructions simultaneously. The main approaches are deepening the pipeline and increasing the number of internal functional units. It is measured by IPC (instructions per cycle), the reciprocal of CPI. Multiple issue lets the CPU issue several instructions per cycle:

    • Static multiple issue: The compiler decides at compile time how instructions are packaged and issued (e.g., VLIW).
    • Dynamic multiple issue: The hardware decides and schedules instruction issue dynamically at run time (superscalar).

    For an ordinary (scalar) pipeline, ideally $$IPC=1$$

    Superscalar: A modern CPU has more than one pipeline. It has multiple execution units (ALUs, FPUs, etc.) and can issue and complete several instructions (e.g., 4–8) in one clock cycle.

    Very Long Instruction Word (VLIW)

    Out-of-order execution: This is the soul of modern architectures. If instruction A must wait for data from memory, the CPU does not simply wait; it skips ahead to execute later instructions B and C that do not need to wait, and finally puts the results back in program order.

    Memory System

    In the von Neumann architecture, executing one instruction requires at least two memory accesses: the first reads the instruction, and the second either reads the data the instruction needs from memory or writes back data produced or modified by an earlier instruction. This limits the speed of the computer and is called the von Neumann bottleneck.

    To relieve this bottleneck, we can add a cache between the CPU and main memory, keeping frequently used instructions and data closest to the CPU and reducing the number of direct memory accesses.

    In real CPUs, we also use Dynamic Random Access Memory (DRAM) to bridge the cache and the disk. It is the core technology of what is commonly called "memory" (RAM) in our computers and phones.

    The Principle of Locality and the Memory Hierarchy

    At any moment, a program accesses only a relatively small portion of its address space. This is the principle of locality:

    • Temporal locality: If a data item is accessed, it is likely to be accessed again soon (e.g., in a loop body). Strategy: keep recently accessed data close to the processor.
    • Spatial locality: If a data item is accessed, items with nearby addresses are likely to be accessed soon. Strategy: move data to the upper level in blocks consisting of several consecutive words.

    This principle runs through the entire design of the memory system.

    The resulting memory hierarchy: levels closer to the processor are faster, smaller, and more expensive (registers → cache → main memory → secondary storage). Two key timing metrics:

    • Hit time: The time required to access the current level.
    • Miss penalty: On a miss, the time required to move the corresponding block from the lower level to the upper level.

    Main Memory

    Word addressing and byte addressing

    • Word storage location: A memory location that holds one machine word.
    • Byte storage location: A memory location that holds one byte.
    • Word address: The address of a word storage location.
    • Byte address: The address of a byte storage location.
    • Word-addressable computer: The smallest addressable unit is a word storage location.
    • Byte-addressable computer: The smallest addressable unit is a byte storage location.

    Technical specifications of main memory

    • Storage capacity: The total number of storage locations in a memory, usually expressed in words (W) or bytes (B).
    • Access time: The memory access time, i.e., the time from issuing a read command until the operation completes and the data are placed on the data bus.
    • Memory cycle time: The minimum interval between two consecutive read/write operations.
    • Memory bandwidth: The amount of information the memory can access per unit time, expressed in words/s, bytes/s, or bits/s.

    Static Random Access Memory (SRAM)

    SRAM stores information in bistable flip-flops (latches); a typical storage cell consists of six transistors. As long as power is applied, the information is retained without refreshing, and reads are nondestructive, so no rewrite is needed after a read. SRAM is therefore fast and its peripheral control circuitry is simple. The cost is many transistors per cell, which means low density, high power consumption, and high price, so SRAM is generally used only for caches, which are small but must be fast.

    Dynamic Random Access Memory (DRAM)

    DRAM stores information as charge on a capacitor (charge represents 1, no charge represents 0). Because capacitors leak, DRAM must be refreshed periodically (typically row by row every few milliseconds). Each cell needs only one transistor and one capacitor, so density is high and cost is low; however, reads are destructive and must be followed by a rewrite, and DRAM is slower than SRAM. The address pins are usually multiplexed between row and column addresses (latched in turn by the RAS and CAS signals) to reduce the number of chip pins.

    Read-Only Memory (ROM)

    In ROM, the stored information must be written before operation; during operation it can only be read, not written.

    Sequential and Interleaved Memory

    Sequential memory: Because programs usually have spatial locality (code and arrays are usually executed and read sequentially), consecutive read requests from the CPU "pile up" on the same memory bank. Since the same chip can serve only one access per cycle $T$, after reading address 0 the CPU must wait until time $T$ has elapsed before it can read address 1. $$t_{\text{total}} = n \times T$$ Interleaved memory: When the CPU reads addresses 0, 1, 2, 3 consecutively, the requests are sent to Bank 0, Bank 1, Bank 2, and Bank 3, respectively. The banks are independent hardware and can work in parallel. After sending a command to Bank 0, the CPU does not need to wait for Bank 0 to finish; after a short transfer time $t$, it can immediately send a command to Bank 1. This forms a pipeline-like structure. $$\boxed{t_{\text{total}} = T + (n - 1) \times t}$$

    Fault Tolerance and Error Detection

    • MTTF (Mean Time To Failure): The average time a system operates normally; larger means more reliable.
    • MTTR (Mean Time To Repair): The average time to repair the system after a failure.
    • MTBF (Mean Time Between Failures): $MTBF = MTTF + MTTR$.
    • Availability: $\boxed{\dfrac{MTTF}{MTTF+MTTR}}$.

    In a coding system, the number of bit positions in which two valid codes (codewords) differ is called the distance between the two codewords, also known as the Hamming distance, denoted $d$. For example, the codewords 10010 and 01110 differ in 3 positions, so $d=3$.

    The minimum distance between any two codewords in the whole coding system is the code distance of that system. Whether a code can detect or correct errors depends on its minimum distance.

    • To detect $D$ bit errors within a codeword, the minimum distance must satisfy $L\ge D+1$.
    • To correct $C$ bit errors within a codeword, the minimum distance must satisfy $L\ge 2C+1$.

    Parity Check Code

    Core idea: Append one bit, 1 or 0, so that the entire code contains an odd or even number of 1s; these are called odd parity and even parity, respectively.

    EExample

    Suppose the original data are 1011001.

    1. Count the 1s in the original data: there are 4 1s.
    2. Even parity: The number of 1s is already even, so append 0. The transmitted data are 10110010.
    3. Odd parity: The number of 1s must be made odd, so append 1. The transmitted data are 10110011.

    Hamming Code

    Parity checking can detect a single-bit error but cannot locate it. A Hamming code uses multiple check bits, each performing a parity check over a group of data bits, so that it can not only detect a single-bit error but also locate and correct it.

    Number of check bits: With $n$ data bits and $k$ check bits, we need $$\boxed{2^k \ge n+k+1}$$ (the combinations of the $k$ check bits must represent "no error" and also identify any of the $n+k$ possible error positions). For example, when $n=4$, take $k=3$ to form a $(7,4)$ Hamming code.

    Positions of check bits: Check bits are placed at positions $2^0,2^1,2^2,\dots$ (i.e., positions 1, 2, 4, 8, …), and the remaining positions hold data bits.

    Grouping rule: The $j$-th check bit $P_{2^{j-1}}$ covers all positions whose binary position number has a 1 in bit $j$ (including itself), using even parity:

    • $P_1$ (position 1) → checks positions 1, 3, 5, 7, 9, …
    • $P_2$ (position 2) → checks positions 2, 3, 6, 7, 10, 11, …
    • $P_4$ (position 4) → checks positions 4, 5, 6, 7, 12, …
    • $P_8$ (position 8) → checks positions 8–15, …

    Error correction (syndrome): The receiver recomputes even parity over the same groups to obtain a $k$-bit syndrome $S_k\cdots S_2S_1$. If it is all 0, there is no error; otherwise, the value of the syndrome is the position of the erroneous bit, and inverting that bit corrects the error.

    The minimum distance of a Hamming code is $d=3$, so it can correct a single-bit error or detect a double-bit error; adding one overall parity bit (the extended Hamming code, SEC-DED) enables "correct 1, detect 2."

    EExample

    Encode the 4-bit data $D_1D_2D_3D_4=1010$ with a $(7,4)$ Hamming code. The bit order is P1 P2 D1 P4 D2 D3 D4 (positions 1–7), i.e., D1=1 (position 3), D2=0 (position 5), D3=1 (position 6), D4=0 (position 7). Using even parity:

    • $P_1=D_1\oplus D_2\oplus D_4=1\oplus0\oplus0=1$ (group {1,3,5,7})
    • $P_2=D_1\oplus D_3\oplus D_4=1\oplus1\oplus0=0$ (group {2,3,6,7})
    • $P_4=D_2\oplus D_3\oplus D_4=0\oplus1\oplus0=1$ (group {4,5,6,7})

    The codeword is 1011010. If position 5 is corrupted, giving 1011110, the receiver recomputes the syndrome: $S_1=1,\ S_2=0,\ S_4=1$, i.e., $S_4S_2S_1=(101)_2=5$, which identifies position 5 as the erroneous bit; inverting it corrects the error.

    Cyclic Redundancy Check (CRC)

    CRC has far stronger error-detection capability than parity checking. Its mathematical basis is the generator polynomial $G(x)$ and modulo-2 division. Modulo-2 division is essentially addition and subtraction without carries or borrows, i.e., a bitwise exclusive OR (XOR) of corresponding bits.

    Computation steps:

    1. Choose the generator polynomial $G(x)$: The sender and receiver agree on a fixed binary string (e.g., the generator polynomial $x^3 + x + 1$ corresponds to the binary string 1011). Suppose it has $K+1$ bits.
    2. Append zeros to the data: Append $K$ 0s to the end of the original data ($K$ is the highest power of the generator polynomial, i.e., the length of the binary string minus 1).
    3. Modulo-2 division: Divide the zero-padded data by the generator polynomial.
    • If the leading bit of the current dividend is 1, the quotient bit is 1; XOR bitwise.
    • If the leading bit of the current dividend is 0, the quotient bit is 0; shift down (equivalent to dividing by 000...0).
    1. Obtain the CRC: At the end of the division, the remainder (always $K$ bits long, padded with leading 0s if shorter) is the CRC check code. Replace the appended zeros with this remainder, i.e., append it to the original data, and transmit.
    EExample

    Generator polynomial $G(x)=x^8+x^5+x^4+1$ Original data 101100 Therefore, the CRC check code appended to the original data is 11111011.

    Cache

    Data can be mapped from main memory into the cache in the following ways:

    • Direct mapping: Each memory block can be placed in only one fixed location in the cache. The implementation is simple, but the conflict rate is high.
    • Fully associative mapping: Any memory block can be placed in any location in the cache. This is flexible and has a low conflict rate, but the lookup circuitry is extremely complex and costly.
    • Set-associative mapping: The cache is divided into several sets; each block can be placed only in one fixed set but in any location within that set. This compromise between the previous two is the most common choice in modern CPUs.

    • Offset (block offset): The low-order address bits, which select the byte within a block; the number of offset bits is $\log_2$ (bytes per block).
    • Index: The middle bits, which select the cache line (direct mapping) or the set (set-associative); a fully associative cache has no index bits (the address is entirely tag + offset).
    • Tag: The high-order address bits, stored in the cache and compared to determine a hit; each line also needs a valid bit indicating whether it holds valid data.

    $$\text{Total cache size} = \text{number of lines }\times(\text{block size }+\text{ tag size} +\text{valid bit})$$ The "capacity" usually quoted refers only to the data blocks. In a set-associative cache, set number = block address mod number of sets.

    Classification of Misses (the 3Cs)

    • Compulsory miss (cold-start miss): The first access to a block that has never been in the cache.
    • Capacity miss: A block is evicted because the cache is too small and is then accessed again.
    • Conflict miss (collision miss): A miss caused by multiple blocks competing for the same set. Fully associative caches have no conflict misses.

    Write Policies

    • Write-through: Every write to the cache is also written to main memory; usually paired with a write buffer so that the processor does not have to wait for the main-memory write to complete.
    • Write-back: Each block has a dirty bit, and a modified block is written back to main memory only when it is replaced.
    • Write allocate: On a write miss, the block is first brought into the cache and then written (usually paired with write-back); write-through usually uses "no write allocate."

    Replacement Policies

    • LRU (Least Recently Used): Replaces the block that has gone unaccessed for the longest time; high hit rate but complex to implement.
    • LFU (Least Frequently Used): Keeps a counter of accesses for each block and replaces the block with the fewest accesses; however, blocks that were hot in the past may linger for a long time, so it does not reflect recent locality well.
    • Random: Chooses a block at random; simple to implement.
    • FIFO (First In, First Out): Replaces the block that entered the cache earliest.

    Performance Evaluation

    Let $N_c$ be the total number of accesses completed in the cache and $N_m$ the total number of accesses completed in main memory. The hit rate $h$ is $$h=\frac{N_c}{N_c+N_m}$$ Let $t_c$ be the cache access time on a hit and $t_m$ the main-memory access time on a miss. The average cache/main-memory access time $t_a$ is $$\boxed{t_a =ht_c+(1-h)t_m}$$ and the access efficiency is $$e=\frac{t_c}{t_a}=\frac{t_c}{ht_c+(1-h)t_m}$$

    Virtual Memory

    Problems that virtual memory is designed to solve:

    • Insufficient main-memory capacity.
    • In multiuser, multitasking systems, multiple users or tasks share memory and run concurrently; the actual memory each program occupies cannot be determined at programming time and must be allocated dynamically at run time.

    The virtual-memory solution is to build a page table, which establishes the correspondence between virtual addresses and physical addresses. Users can access only virtual memory, and the page table links virtual memory to physical memory.

    Because the page-table mapping can be arbitrary, when a program runs its pages can be loaded into any available frames without needing to be contiguous. This solves the memory contiguity problem.

    If every access to a physical address also required an access to the page table, each operation would effectively require two memory reads, and this time cost is unacceptable. We therefore build a cache for the page table, called the TLB (Translation Lookaside Buffer).

    • Cases during an access:
    • TLB miss: The translation is not in the TLB and must be loaded from the page table into the TLB (TLB misses are far more frequent than page faults).
    • Page in memory: The page table entry (PTE) holds the physical page number, and translation completes normally.
    • Page not in memory: A true page fault occurs, triggering an operating-system exception handler that brings the page in from disk.

    Because page faults are extremely costly (disk access), virtual memory generally uses fully associative placement + write-back + approximate LRU to minimize the page-fault rate.

    The CPU has a dedicated module called the MMU (Memory Management Unit), which looks up the TLB and PTEs and intercepts unauthorized accesses.

    Bus System

    A bus connects two or more functional units of a computer and allows them to exchange data.

    For a bus, the number of parallel data paths is called the bus width; for example, a 64-bit-wide bus can transfer at most 64 bits (8 bytes) of information at a time. The rate at which data are transferred over the bus is called the bandwidth, and the interval from issuing a data transfer request to the actual transfer of data is called the latency.

    By connection, buses can be divided into internal buses, system buses, and I/O buses.

    By function, buses can be divided into data buses, address buses, and control buses.

    Bus Standards

    Bus performance metrics:

    • Bus width: Usually the number of bits of the data bus.
    • Bus frequency: 1 / (time for one data transfer).
    • Bus bandwidth: The data transfer rate of the bus, i.e., the number of bits transferred per unit time, usually measured in bytes transferred per second.
    • Bus multiplexing: Transmitting multiple signals over one signal line by time sharing.

    Bus Structure

    • Data transfer bus: data, address, and control lines.
    • Arbitration bus: includes bus request lines and bus grant lines.
    • Interrupt and synchronization bus: handles prioritized interrupt operations; includes interrupt request lines and interrupt acknowledge lines.
    • Common lines: include clock lines, power lines, ground lines, reset lines, and power-up/power-down timing signal lines.

    Bus Arbitration

    Devices connected to a bus are either masters or slaves, and the period during which a master continuously occupies the bus is called the bus tenure. A master can control the bus and initiate a bus cycle, such as the CPU; a slave can only respond to requests from a master, such as memory. In each bus operation, only one master can hold control of the bus, but one or more slaves may participate at the same time.

    Centralized Arbitration

    Daisy chaining: Polling proceeds step by step along the BG (bus grant) line.

    • Advantages: simple to implement; easy to add devices.
    • Disadvantages: sensitive to circuit faults; fixed polling priority.

    Counter-based polling: A counter records the arbitration count; if the count equals a device's interface number, that device is granted the bus; otherwise the counter is incremented and polling continues.

    • Advantages: the priority order can be changed conveniently by changing the counter's initial value.
    • Disadvantages: extra control lines are needed to transmit the interface number.

    Independent requests: Every interface can issue requests independently, and the bus controller arbitrates using an internal priority circuit.

    • Advantages: fast response; relatively flexible.
    • Disadvantages: too many control lines.

    Distributed Arbitration

    • Self-selection distributed arbitration (each device independently determines whether it is the highest-priority requester. During arbitration, each device reads back and analyzes the combined signals on the request lines and determines from them whether it may take control of the bus).
    • Collision-detection distributed arbitration (each device requests the bus independently; when several devices use the bus at the same time a collision occurs, which is detected, and one of the colliding devices is selected according to some policy (CSMA/CD, carrier sense multiple access with collision detection)).
    • Parallel contention distributed arbitration
    • When a device has a bus request, it places its unique arbitration number on the shared arbitration bus.
    • Each arbiter compares the number on the arbitration bus with its own.
    • If the number on the arbitration bus is larger, the device's bus request is not granted, and it withdraws its arbitration number.
    • Finally, the winner's arbitration number remains on the arbitration bus.

    Bus Operations

    Read/write operations

    • Read: data transfer from a slave to a master (address–command–data)
    • Write: data transfer from a master to a slave (address–data–command)

    A write operation from one master to multiple slaves is called a broadcast. A read operation from multiple slaves to one master is called a broadcall.

    Bus cycle:

    • Request and allocation phase: The master requests use of the bus, and the bus arbiter decides who gets the bus for the next transfer cycle.
    • Addressing phase: The master that has obtained the bus sends the address of the slave to be accessed and the relevant commands, starting the slave involved in the transfer.
    • Transfer phase: The master and slave exchange data.
    • Completion phase: The master's information is removed from the bus, and the master relinquishes the bus.

    Bus Communication Methods

    There are four main ways for a bus to coordinate the timing of the master and slave during a transfer:

    • Synchronous communication: All components work in fixed steps driven by a common clock. It is regular, simple to control, and has a high transfer rate, but it must be based on the slowest device, and bus length and flexibility are limited.
    • Synchronous read
    • Synchronous write
    • Asynchronous communication: There is no common clock; handshake (acknowledgment) signals coordinate the transfer. The master issues a Request, and the slave replies with an Acknowledge when ready; two handshake lines must be added. Depending on whether request and acknowledge constrain each other, there are three levels: non-interlocked (e.g., memory access), semi-interlocked (e.g., access to shared memory), and fully interlocked (e.g., network communication); fully interlocked is the most reliable but the slowest. It is flexible and can accommodate devices of different speeds, but control is complex and speed is relatively low.

    • Semi-synchronous communication: A compromise between synchronous and asynchronous: it keeps a common clock but allows a slow slave to assert a wait signal ($\overline{\text{WAIT}}$/READY) to insert several wait cycles, combining the simplicity of synchronous with the flexibility of asynchronous communication.

    • Split-transaction communication: A bus cycle is split into a "request subcycle" and a "reply subcycle," and the bus is released for other devices between the two (e.g., while memory prepares the data). Both subcycles use synchronous, one-way transfers without waiting for the other side to answer, so whenever the bus is occupied it is doing useful work with no idle waiting. It has the highest utilization but the most complex control and is mostly found in mainframes.

    Baud rate: The total number of bits transmitted per unit time (including overhead bits such as start, parity, and stop bits), in bps. Bit rate: The number of valid data bits transmitted per unit time (the effective information rate after excluding overhead bits), in bps. Relationship: bit rate = baud rate $\times\ \dfrac{\text{valid data bits}}{\text{total bits per character}}$

    In an asynchronous serial transmission system, each character consists of 1 start bit, 8 data bits, 1 odd parity bit, and 1 stop bit. Suppose the baud rate is 1200 bps (all 11 bits counted).     I/O System

    As CPU performance has improved rapidly, I/O has gradually become the system bottleneck, especially for I/O-intensive applications.

    An I/O system consists of I/O software and I/O hardware.

    The main tasks of I/O software are to input user programs and data into the host, output results to the user, and coordinate the operation of the I/O system with the host. It relies on two kinds of instructions:

    • I/O instructions: A class of machine instructions reflecting how the CPU exchanges information with I/O devices (e.g., IN/OUT).
    • Channel instructions (Channel Command Words, CCW): Instructions designed specifically for I/O systems with channels. They are executed by the channel and are not part of the CPU instruction set. After the CPU executes the corresponding I/O instruction, the channel instructions take over the management of the I/O devices. They are generally long and specify the starting data address, the number of words to transfer, the device code, the command code, and so on. The command code specifies the particular operation of the I/O device, and the device code acts as the device address, used to select among multiple devices.

    I/O hardware: An I/O system with interfaces generally consists of interface modules and I/O devices. The interface circuitry contains data transfer paths, control signal paths, and the associated logic; more complex systems have a channel structure.

    I/O Interfaces

    An I/O interface, also called an adapter, refers to the hardware circuitry and associated software control placed between the host and I/O devices. Interfaces are needed for device selection, data buffering (to smooth the speed difference between host and device), serial–parallel and voltage-level conversion, transmitting control commands, and monitoring and recording device status for the CPU to query.

    Functions and Composition of I/O Interfaces

    An I/O interface circuit connected to a bus contains four kinds of signal lines: device select lines, data lines, command lines, and status lines. Its functions correspond to its components as follows:

    • Address selection: implemented by the device selection circuit.
    • Command transfer: provided by a command register and a command decoder.
    • Data transfer: provided by a data buffer register (DBR) connected to the data lines.
    • Device status reporting: provided by status flip-flops, such as the interrupt request flip-flop, the interrupt mask flip-flop, and operation flag flip-flops (the done flip-flop D and the busy flip-flop B).

    I/O Data Exchange Methods

    The CPU exchanges information with I/O devices in four ways: programmed polling, program interrupts, DMA, and channels.

    Programmed Polling

    Programmed polling is the simplest input/output method. Data transfer is controlled entirely by the program and proceeds under the active control of the CPU: when an I/O operation is needed, the CPU suspends the main program and executes the device service routine.

    • Advantages: CPU and peripheral operations can be synchronized; the hardware is simple.
    • Disadvantages: The CPU polls in a loop, wasting CPU cycles and resources.
    • Generally used in microcontrollers or digital signal processing (DSP).

    Polling is carried out by I/O instructions: setting bits of the interface control register to "0" or "1" to control the device, testing the device's "busy/ready" status to decide the next step, and transferring data.

    DMA

    DMA (Direct Memory Access) is an I/O method performed entirely by hardware, which can exchange blocks of data between main memory and I/O devices at high speed. Its basic idea is that a hardware DMA controller takes over control of the bus from the CPU, and data are exchanged directly between main memory and the I/O device without passing through the CPU. The preparation before and the processing after a transfer are handled by the CPU's management program (preprocessing and postprocessing via program control or interrupts); the DMA controller is responsible only for the data transfer.

    Basic components of a DMA controller:

    • Memory address register (AR): Holds the main-memory address of the data to be exchanged; incremented by 1 after each transfer.
    • Word counter (WC): Records the length of the data block to be transferred.
    • Data buffer register (BR): Temporarily holds the data for each transfer.
    • Device address register (DAR): Holds the I/O device code or the addressing information for secondary storage.
    • Control/status logic: Manages the DMA transfer process.
    • Interrupt mechanism: Raises an interrupt when the word counter overflows (a block of data has been transferred).

    Three ways for DMA to exchange data with main memory:

    • Halting CPU memory access: The CPU relinquishes the bus and stays in a hold state. Control is simple, but the CPU's use of main memory is not fully exploited; suitable for high-speed block transfers.
    • Cycle stealing: Each DMA data transfer occupies ("steals") one or more CPU cycles. If the CPU is not accessing memory, there is no conflict; if the CPU is accessing memory, it releases the bus when its access finishes; if both request at the same time, DMA has priority. This is the most commonly used method and suits cases where the I/O read/write cycle is longer than the main-memory cycle.
    • Alternating DMA and CPU memory access: The CPU cycle is divided into two parts, dedicated to CPU access and DMA access respectively; there is no need to request and release the bus, so transfers are fast and efficient, but control is complex.

    A DMA transfer proceeds in three phases: preprocessing (the CPU presets the DMA controller with the transfer direction, device address, main-memory address, and word count), data transfer (in units of data blocks, implemented as a loop), and postprocessing (checking the data and deciding whether to continue, performed by the interrupt service routine).

    Channels

    A channel is an independent component of a computer system that manages and controls peripherals on behalf of the CPU and can execute a limited set of I/O instructions (channel commands). A host can connect multiple channels, and each channel can connect multiple devices of different speeds and types, increasing the parallelism between the host and the channels, among channels, and among devices on the same channel. A four-level connection is usually used: host–channel–device controller–I/O device. After the CPU starts a channel, the channel automatically fetches channel instructions from memory and executes them, interrupting the CPU only when the data exchange is complete.

    A further development of the channel is the I/O processor (IOP): a component of the computer system (not an independent computer) that can work in parallel with the CPU and provides high-speed DMA processing; some also provide data conversion, searching, and word assembly/disassembly (e.g., the Intel 8089).

    Overall, the evolution of I/O control methods is a process of progressively freeing the CPU from specific I/O operations: CPU directly controls peripherals → I/O controllers are added → interrupt mechanisms are added → DMA mechanisms are added → dedicated I/O processors → independent I/O processors.
